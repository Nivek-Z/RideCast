# 模型质量升级：第二轮独立验收预登记（草案）

协议标识：`quality-round2`。登记日期：2026-11-11（Asia/Shanghai）。本草案先固定新的未见世界/时段、等预算比较和验收门槛；候选算法仍在开发，正式运行前须提交开发冻结版本并保存源码摘要。此时没有生成或查看以下新case的最终测试数据。

## 第一轮失败保留与隔离

第一轮quality-v1使用冻结提交6495437和种子101/202/303/404/505的2026年3月历史，完成10case且源码未变，但平均MAE只比v1改善8.0234%，最差case退化6.7318%，没有达到15%改善与退化不超5%的目标；10/10优于验证选定朴素基线仍不能抵消失败门槛。`reports/model-quality-round1.json`逐字节保留原results.json，其protocol/source hashes不改；Markdown明确未通过、未晋升主模型，原始完整产物继续保留于var/quality/final-v1。

第一轮在被查看后只能用于失败诊断和开发参考，不能再次称为未见验收。第二轮的算法可以基于开发数据及已公开失败诊断作实质改进，但必须在接触本轮新测试数据前完成选择；不得删除第一轮、把两轮分数择优拼接、只挑本轮好case或降低原门槛。

## 第二轮固定矩阵

新世界种子为 **606、707、808、909、1001**。每seed分别运行normal和pressure，共10case；3×3区域、60分钟桶、45天，观测从 **2026-06-01T00:00:00+08:00** 起，到2026-07-16 00:00止（右端不包含）。world seed与演化seed相同，模型初始化seed固定42。生成器仍为seeded-city-v2 / absolute-time-v2，不修改世界难度。

| 情景 | 预先固定条件 |
| --- | --- |
| normal | 自然演化与已有程序化公告日程，无额外倍数覆盖 |
| pressure | rain_multiplier=2、traffic_multiplier=1.3、supply_multiplier=0.8；z_000在 **2026-07-13 18:00–22:00（Asia/Shanghai）** 有提前公告的强度1.5活动 |

活动落在测试末段，未来日程可知，但未来实测天气、实际供给、潜在状态和需求不可作为默认特征。压力倍数贯穿整段历史，不能解读为随机干预的因果识别。每世界独立重训，报告不等于单模型零样本迁移或实际城市效果。

## 等预算与信息边界

冻结的legacy v1与第二轮候选读取同一份不可变面板，均采用70/15/15时序切分、lookback24、horizon3、units32、batch_size128、learning_rate0.001、最多30轮、seed42、tune=false；候选计数损失固定Poisson。早停和具体候选实现由开发阶段选择并在正式运行前冻结，不在本轮测试上调节。

v2验证前65%用于epoch、季节基线和融合权重选择，后35%独立校准残差带；跨该界线的多步标签窗口排除。本轮45天数据必须独立校准，不能启用小样本复用验证的fallback。神经融合权重仍限0/0.25/0.5/0.75/1；透明报告纯神经、实际服务、所选基线及每case部署类型，纯季节回退不能被称为纯神经改善。

第二轮增加严格因果的近期水平校准，修正持续的总量偏差。它只把预测起点以前最近12或24小时已经发生的真实需求，与同一冻结模型按各自过去起点特征得到的h1回推作比较，因子为 `clip((Σpast y+20)/(Σpast μ+20),0.5,2)^strength`。策略网格预先固定为禁用（window_hours=0,strength=0），或window_hours为12/24、strength为0.5/1，prior_count恒20。策略与神经权重联合只在前段验证MAE选择，后段校准和测试不再改策略；每个新起点按固定策略只汇总其自身以前的数据，不把未来what-if情景改写到过去h1回推。此滚动因子不是重新拟合神经网络，也不能把它带来的效果称为纯神经改善。

测试明细保留 `neural_demand`（原神经输出）、`baseline_demand`、`uncalibrated_demand`（权重融合）、`adaptation_factor` 和实际 `predicted_demand=uncalibrated_demand×adaptation_factor`；metadata.adaptation记录选中参数与信息来源。runner检查因子有限、为正、在预定裁剪策略范围内，同起点/区域跨预测步一致，以及完整服务公式。纯神经、校准前融合及最终服务指标分别报告。

主朴素基线仍从legacy v1验证MAE在最近值、前日同期和前周同期中选择；测试同时报告全部朴素基线，测试后最优基线只能作为诊断。所有特征与缩放严格遵守起点信息边界；预测单元必须完整一致，不取交集删样本。runner检查实际配置、时间边界、完整测试范围与选择/校准窗口数。

## 门槛保持不变

1. 10case等权平均MAE相对等预算v1至少改善 **15%**。
2. 至少 **8/10** case优于验证集选定的朴素基线。
3. 每个case相对v1的MAE退化均不超过 **5%**。
4. 所有case预测有限、非负、区间顺序正确；完整预测单元/真值一致、源码冻结和接口兼容通过。

任一门槛未达到则第二轮如实未通过，不继续在这些新测试上追分。第一轮失败继续并列披露。改进幅度不替代绝对误差、偏差、城市总量、高峰和区间表现。

## 结果与可复现性

完整指标与第一轮相同：MAE/RMSE/WAPE/sMAPE、bias/bias_percent、逐区/逐步、高峰07:00–10:00与17:00–21:00、非高峰、按同起点/目标/步长汇总区域的城市误差、区间覆盖/宽度、冷启动和3次热forecast时延。WAPE和bias%已乘100，分母为0返回null。保留纯神经与实际融合预测，绝不把多个起点的重叠目标求和为独立订单。

runner的 `--protocol round1` 保留原case和默认payload；原报告SHA不因runner后续参数化而伪造更新。`--protocol round2` 使用本矩阵并保存独立protocol_sha256，冻结范围包括生成器/data、legacy/new特征与模型、seasonal.py、rate_profile.py、adaptation.py、runner及两份协议文档。正式新代码会产生新source hashes，必须与第一轮各自真实版本区分。

以下命令只列出协议，不访问数据：

```bash
python scripts/evaluate_quality.py --protocol round2 --list-cases
```

候选开发冻结并提交后才可运行：

```bash
python scripts/evaluate_quality.py --protocol round2 --run --output var/quality/final-round2
```

完整产物进入忽略的var目录，小体量最终报告另存reports/model-quality-round2.json/md。草案转为正式执行记录时应记录冻结提交及摘要；不在未执行前填写通过数字。

第二轮候选加入训练集内拟合的正则Poisson条件率层，再由GRU学习残差；其参数只来自训练窗口，不使用验证/测试标签初始化。最大30轮指神经训练预算相等，条件率拟合另有最多30次Newton迭代，因此并非总计算预算或参数量完全相等；必须另报拟合迭代、实际训练耗时和完整预测时延。日历、区域、历史水平及天气输入仍遵守预测起点的信息边界。

# 建模设计、评价与实验边界

## 目标

对区域z预测未来H桶发起请求数。API的forecast_origin为首个预测桶左端，第h步时间为 `forecast_origin+(h-1)×bucket_minutes`，历史严格早于forecast_origin。默认1小时桶、过去24桶、未来3桶，均可配置。合成数据包含完整发起请求；真实数据若只能提供已完成行程，则模型目标明确为completed_trips。乘客数是需求解释变量的历史滞后值，与订单数分开，不把目标时段人数当作已知输入。

## 特征与模型

当前v2的特征版本为 `origin-aware-profile-v3`，架构为 `conditional_poisson_rate_residual_gru`。模型保留过去24桶短序列，并补充从更早已观察历史提取的日/周季节信息，因此显式lags可超过GRU的lookback；两者均不能访问预测起点之后的观测。

历史分支包含log1p需求、接触区域需求均值、log1p乘客、温度、log1p降雨、风速、拥堵和log1p供给；新增当地小时的1–6阶sin/cos谐波、历史节假日及历史活动强度。孤立区域的邻域需求回退到自身。未来分支包含当地时间/周内周期、节假日/调休、已公告活动、预测步长及起点持续天气/交通/供给。静态分支为区域质心经纬度、log1p人口/岗位、吸引力、土地用途kind的one-hot和区域one-hot。`base_demand`仍未直接输入模型；仿真seed、潜在状态、未来需求与生成器强度公式也不输入模型。完整有序字段见metadata.feature_schema。

`seasonal.py`按当地日历时刻取前1/2/3天及前周同期，提供可用性标志；汇总过去6/24/168小时需求及过去7/14天同一时刻的指数加权均值、标准差和覆盖率。季节画像优先匹配目标的工作/休息日类型，缺少可比历史时回退并暴露缺失标志；夏令时下按当地钟点对齐而非固定UTC减24小时。最近水平修正仅比较历史窗口和已发生的匹配前日时刻。

训练集内先拟合分区域正则Poisson条件率模型，输入日历谐波、已公告活动、降雨、历史24/168小时水平与近期变化；仅用训练窗口的特征和标签，L2核惩罚0.02、最多30次带回溯Newton迭代。没有活动变化的区域可从有证据区域借用活动系数，并调整截距保证常量训练输入的原预测不变；没有任何证据时不杜撰系数。条件率权重作为冻结参数层存入.keras，既不是未来标签特征，也不读取仿真公式。共享GRU和逐步Dense头学习相对此平滑条件率的有限对数修正，避免硬依赖较旧的14天需求锚点。零初始化使网络从训练拟合率出发，输出为正的订单数量尺度，不再通过log1p-MSE后取expm1作为默认点预测。默认最多30轮、Adam梯度裁剪、Poisson计数损失；Poisson实现为预测值减真实值乘log预测值，与完整负对数似然相差仅依赖目标的常数，数值可为负。可选Huber(delta=3)计数损失；二者都不能当作订单尺度MAE读数。[Keras损失定义](https://keras.io/api/losses/probabilistic_losses/)

验证集选择神经预测与起点可用基线的融合权重。基线候选包括最近值、前日同期、前周同期、因果季节画像和训练拟合的日历条件率；权重网格为0/0.25/0.5/0.75/1。metadata.blending.deployment区分 `neural`、`neural_seasonal_blend`、`seasonal_fallback`；权重0表示实际服务季节回退。metadata.metrics.model报告最终服务效果，metrics.neural单列.keras网络原始输出（含训练拟合条件率层），uncalibrated_model列出水平校准前融合效果。测试明细保存predicted_demand/neural_demand/baseline_demand/uncalibrated_demand/adaptation_factor；不能把统计先验、回退、融合和后校准的全部收益归因于GRU本身。

近期水平校准只使用当前起点之前已经观测的真实需求，与冻结模型在对应过去起点的h1回推比较。对最近12或24小时，使用带20单伪计数的实际/期望总量比，裁剪[0.5,2]后取0.5或1次幂；也可关闭。5种政策与5种融合权重只在前段验证中选择，后段只校准区间，测试仅滚动使用其起点以前观测。回推使用每个历史起点可知的输入，未来what-if情景不施加到历史；这不是事后读取当前目标来修正预测。metadata.adaptation保存选择和假设。

v1的 `origin-aware-v1` 特征及log1p-MSE GRU完整保留在legacy_features.py/legacy_ml.py。统一forecast入口按模型特征版本分派，旧`.keras`、旧曲线和旧指标仍可使用，不会重新解释为v2。固定栅格ConvLSTM仍未成为唯一方案，便于未来接不规则区域；首期也不引入大Transformer。相关比较和论文链接见research-notes.md。

## 信息边界与评估

1. 原始连续时序按70%/15%/15%划分训练、验证、测试。最早lookback桶用于历史，不产生训练标签；每个多步目标窗口必须完整位于所属分区。
2. 同一预测起点只访问严格早于该起点的订单/人数/天气/供给。验证/测试允许使用自身已过去的真实历史，属于滚动起点评价；不会读本次起点以后才知道的状态。
3. 缩放均值/标准差仅由训练窗口拟合并随模型归档。模型未来天气默认使用最后已知值，回测与在线预测复用同一函数；虚拟世界的未来真值可供仿真查看，但不能暗中送给模型。
4. 在完整验证时间段内再按时间划前65%用于选择，后35%用于区间校准；跨该界线的多步标签窗口排除。epoch、计数损失候选、基线和融合权重只在前段按MAE选择，恢复最佳轮权重。后段标签不参与选择；极小数据无法再分时有明确fallback，metadata.validation_subsplit.independent_calibration=false，不宣称独立校准。
5. tune=true实际比较同一GRU结构的Poisson和Huber计数损失候选，默认loss=poisson；tune=false仅训练指定损失。基线和融合也只用前段验证。朴素多步同期若尚不可知会继续向过去回退，没有足够历史退到最近值。测试只在全部选择冻结后最终评估，不用测试追选种子、轮数或融合权重。

训练时shuffle仅发生于已切好的训练窗口，不随机拆分原始时间。模型版本保存每区/每步指标、候选验证分数、曲线及测试明细。测试分区内多步窗口可以覆盖相同目标时刻，统计单元为forecast_origin×zone×horizon；所有方法使用相同单元，图表不能把这些重复时刻加总为城市需求。

## 指标与区间

MAE为平均绝对误差，RMSE为均方误差平方根（单位订单）；WAPE为绝对误差和除以真实需求和×100%；sMAPE为 `mean(2*abs(y-p)/(abs(y)+abs(p)))*100%`，二者均0时该项为0。真实需求和为0时WAPE返回null。bias为平均预测减真实值，volume_bias_percent为总量有符号误差占真实总量的百分比。v2的loss/val_loss按候选Poisson或Huber定义，v1为log1p-MSE；曲线的loss_unit动态说明实际损失，不能跨损失比较原始数值，也不能与订单尺度MAE混用。

metadata.metrics.operational提供city、peak、off_peak和high_demand分组指标；城市误差先按同一起点/目标/步长汇总区域，高需求分组阈值仅由训练数据的需求80%分位数确定，不能用测试需求重新选阈值。模型、基线及分步/分区域指标仍保留原路径，便于仪表盘兼容读取。

每个预测步用后段校准集的服务预测绝对残差90%分位数建立对称经验区间，lower下截0；同时报告测试覆盖率和平均宽度。小数据fallback会复用验证数据并明确标记，不能称独立校准。这不是严格校准的条件置信区间，也不是同时覆盖所有区域/时刻的保证；时间依赖和分布变化会改变覆盖。未使用测试残差调整区间。

第一轮预登记研究未达到全部门槛，完整保留于reports/model-quality-round1.json/md，已转为失败诊断，未晋升默认模型。新效果以 `reports/model-quality.md` / `reports/model-quality.json` 的第二轮实际结果为准，第二轮协议见MODEL_QUALITY_PROTOCOL_ROUND2.md；第二轮10case平均MAE2.5254→2.2802（−9.71%），10/10胜出朴素基线，最差退化0.057%；15%进阶门槛未达，保持未通过记录，不在本批测试继续追分。经验区间覆盖85.39%，低于名义90%。第一轮协议见MODEL_QUALITY_PROTOCOL.md，第二轮见MODEL_QUALITY_PROTOCOL_ROUND2.md：5个未用于开发的世界seed各常态/压力情景，等预算比较v1/v2、全部朴素基线、纯神经与服务融合，并检查城市总量、高峰、区域、步长、偏差、区间和响应时延。若预登记门槛未达到，必须保留未通过结论，不能改门槛或换测试种子。

## v1历史结果（开发参考）

以下为已查看的v1历史实验，不是当前v2的独立测试成绩。seed42、3×3城市、45天、100,550发起请求、9,720个区域时间桶；两个候选各最多12轮，由验证集选择。测试4,320个区域/起点/步长预测单元：GRU MAE **3.1886**、RMSE **4.5194**、WAPE **41.01%**；验证集选定主基线为前周同期，测试MAE **4.8366**。所有基线也保留：前日同期在该测试集MAE **3.4801**，因此报告相对主基线34.07%的改进时必须一并说明，不能将其当作优于所有基线34%。区间测试覆盖率 **89.05%**。历史记录见 `reports/demo.json`，若另行生成新版演示，应使用新文件保留原记录。

三种随机世界各28天、同一小模型配置5轮独立重训：模型平均MAE **3.4736**，基线平均 **3.3265**，只有1/3世界优于其验证集选定基线。这个结果提醒模型并非总优，较少种子和短训练只提供有限证据。此实验测试生成器下重复建模稳定性，未评价单个模型跨城市零样本泛化。完整结果与源码复核记录见 `reports/world-benchmark.md` 和JSON。

## 后续实验与真实部署

正式研究可增加更多预先指定种子与时间段、滚动起点交叉验证、稀疏区域及高峰分组、极端天气和活动压力测试、邻域/天气/日历消融，以及供给干预前后离线调配评价。应在新开发集上选方案，再用保留的未见测试区间验证，不能反复追当前测试分数。

合成宏观演化没有经过城市真实分布校准，不支持宣称提升真实出行满意度、降低真实空驶率。调配仅为启发式建议，没有真实执行或交通路径约束。接入真实请求、取消、供给、天气预报及公告活动后，还需数据覆盖检查、漂移监控和真实时序回测，再决定模型启用。

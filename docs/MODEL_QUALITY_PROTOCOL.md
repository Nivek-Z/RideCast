# 模型质量升级：预登记验收协议

协议版本：quality-v1，登记于2026-11-11（Asia/Shanghai）。本协议在生成下列新验收数据、查看其测试区间和训练升级模型之前写入。生成器保持 `seeded-city-v2` / `absolute-time-v2`，禁止改容易度来提高分数。

## 开发与最终验收分离

已有种子7/42/99、2026年1月数据和45天演示已被查看，只能作为开发参考。可新增开发种子11/23、2026-02-01开始的历史，并只依据开发数据的训练/验证分区决定模型结构、损失、训练预算、基线融合和区间校准。升级方案冻结后才运行本协议的最终验收；最终结果不用于继续追分调参。

最终世界种子固定为 **101、202、303、404、505**；每个世界创建两个独立情景，共10个case。每个case均3×3区域、1小时桶、45天，观测从 **2026-03-01T00:00:00+08:00** 起，到2026-04-15 00:00止。世界种子与演化seed相同，模型初始化seed固定42。各世界分别重训，不宣称单模型跨城市零样本迁移。

| 情景 | 预先固定的条件 |
| --- | --- |
| normal | 原始生成器的自然演化与公告活动，未增加倍数覆盖 |
| pressure | rain_multiplier=2、traffic_multiplier=1.3、supply_multiplier=0.8；zone z_000 在2026-04-12 18:00–22:00有事先公告的强度1.5活动 |

压力情景的活动落在最终测试区间，检验未见事件条件；未来计划可知，未来实测天气、实际供给、潜在状态和目标需求仍不可读。压力条件在整个观测期固定，不能解释为突发干预的因果效应。供给变化不是请求标签变化的替代指标。

## 公平预算和比较对象

v1保存在独立的 `legacy_features.py` / `legacy_ml.py`，不改其模型算法。v2与v1使用完全相同的不可变原始面板、70/15/15时序边界、lookback=24、horizon=3、units=32、batch_size=128、learning_rate=0.001、epochs=30、seed=42、tune=false。每种模型可按预先固定的验证规则早停；最大轮数相等并报告实际轮数/训练耗时。v1旧默认12轮的已知结果仅为历史参考，不冒充本次等预算对照。

基线包括最近值、前日同期和前周同期。所有基线严格取预测起点以前观测，多步需要的“同期”若尚不可得则继续向过去回退。主基线依据验证MAE选择；测试结果同时列出全部基线，并列出仅供诊断的“测试后最优朴素基线”，不将其用于训练、预测或模型选择。

多步目标窗口不得跨分区。比较时预测起点×zone×horizon集合及对应真值必须完全一致，不通过删除困难样本产生改善。原始生成器和模型源码SHA256在运行前后保存；运行中有数学实现变化则该次验收不合规。

## 预登记质量目标

以下是升级目标，**未达到时如实报告，不修改门槛使其通过**：

1. 10个case等权的平均MAE，相对等预算v1至少降低15%。
2. 至少8/10个case的v2测试MAE低于该case验证集选定的朴素基线。
3. 任一case相对v1的MAE退化不超过5%。
4. 所有case输出有限、非负、区间顺序正确；预测单元一致、时间信息边界成立、API契约兼容。

单一WAPE不定义“准确率”，也不给测试均值之外的业务精度保证。质量门槛主要衡量相对v1和真实可用基线的改善；30轮也不保证任何神经网络必然胜出。

## 必报指标

每case同时报告v1、v2、主基线及全部朴素基线的MAE、RMSE、WAPE、sMAPE、平均有符号误差bias（预测减真实，单位订单）、总量bias_percent。报告按区域、预测步、当地高峰（07:00–10:00及17:00–21:00左闭右开）与非高峰分组，并报告按同预测起点/目标时刻/步长汇总全部区域后的城市总量误差。

评价单位是forecast-origin×zone×horizon，分区内部重叠目标在各自起点分别计数；城市总量也按同一起点/步长聚合，不把重叠预测相加为独立订单。WAPE真实总量为0时返回null，bias_percent同理。

报告经验区间覆盖率、平均宽度、分步覆盖；区间只能由验证数据校准，不用最终测试残差调整。另测调用forecast整条路径的冷启动和3次热运行时延（含读盘/特征/模型调用，非纯算子耗时），避免只提高分数却破坏仪表盘响应。该时延为本机小样本，没有生产并发保证。

## 复现

`python scripts/evaluate_quality.py --list-cases` 仅展示协议，不生成验收数据。

待模型冻结且记录源码版本后，使用新的空输出目录运行：

```bash
python scripts/evaluate_quality.py --run --output var/quality/final-v1
```

脚本保存完整数据/模型/测试预测于忽略的var目录，生成可追溯的results.json和summary.md。可提交小体量结果报告，不能把私有订单或大模型纳入Git。任何失败case保留错误，不从平均数中悄悄剔除；有失败时总体验收不通过。
